# Home Decor Ideas

A local-first, responsive interior-design inspiration website built with HTML5, CSS3, and vanilla JavaScript. The project does not require a backend, paid API, account system, or framework.

## Project status

- 25 interior design categories.
- 174 starter design records generated from 28 authored seed concepts and 146 category-specific/template seed records.
- The library is **not complete** and does not contain 3,750 individually reviewed designs.
- The image set contains 12 Unsplash photo IDs reused across design records; design-record count is not unique-photo count.
- Prompt Studio is deterministic and template-based. It does not call a live AI model.
- The 20 original tools are retained. The additional engagement layer adds local favorites, history, projects, quiz, recommendations, and prompt history.

## Features

### Inspiration library
- 25 categories, search, category chips, sorting, and load-more pagination.
- Additional style, color, and material facets.
- Design detail dialog, prompt copying, favorites, and recently viewed tracking.
- Eight original curated records are flagged as featured editorial selections. This is not a measure of user popularity.

### Local engagement
- Favorites and recently viewed designs persist in browser local storage.
- Recommendations are based on the categories of saved and recently viewed designs.
- Daily inspiration is selected deterministically from the existing library based on the local calendar date. It is not generated by AI or updated by a live service.
- A weekly design edit rotates deterministically through five existing records; it is a discovery aid, not newly commissioned editorial content.
- Search offers native title/category suggestions and stores up to eight recent search terms locally. Search history is included in the local JSON export and deletion flow.
- Projects support name, room, style, palette, notes, selected inspiration designs, and selected saved prompts.
- Style quiz and rotating creative challenges.
- Prompt history and saved prompts.
- Export and delete controls for this website's local saved data.

### Prompt Studio
- The existing prompt builder remains template-based and local.
- Existing controls cover room, style, palette, room dimensions, furniture, finishes, lighting, materials, mood, camera/composition, quality, realism, aspect ratio, custom instructions, and negative prompts.
- Prompt history and saving are local to the current browser.

### Original free toolkit
The original 20 tools remain: color palette generator, color contrast checker, wall paint calculator, room style quiz, mood board creator, room paint calculator, wallpaper calculator, flooring calculator, tile calculator, furniture layout planner, renovation budget calculator, design cost estimator, area converter, curtain sizing, lumens calculator, gallery wall planner, sofa/rug guide, checklist maker, shopping list maker, and before/after image comparison.

Calculations are planning estimates. Verify dimensions, coverage, waste, prices, fixture specifications, and local requirements before purchasing or construction. The furniture layout is a concept sketch, not a measured plan. Wallpaper roll coverage is entered by the user and does not calculate pattern repeat or roll dimensions automatically.

## Run locally

1. Extract the project ZIP.
2. Open the folder in Visual Studio Code.
3. Run a local static server, for example VS Code Live Server or `python -m http.server 8000`.
4. Visit `http://localhost:8000`.
5. Internet access is required for remote Unsplash photographs. The local tools, prompts, and saved items work without a live AI API.

Service workers require HTTPS or localhost. Opening `index.html` directly using `file://` does not enable PWA/offline functionality.

## Browser storage and privacy

Favorites, recently viewed IDs, projects, prompt history, and saved prompts use `localStorage`. They remain on the same browser profile and device, are not synced, and may be cleared by browser settings. Private browsing modes or browser policies may block or evict storage. Storage quota errors are handled with a user-facing message. Use **Export my saved data** before clearing site data if you want a backup; the export is a JSON file and is not encrypted.

Before/after images are selected locally, size-limited to 5 MB each, and previewed using temporary object URLs. This page code does not upload them. Unsplash image requests go to Unsplash and may expose normal connection metadata to that provider.

No analytics integration is active. No third-party advertising scripts are active in this release. The previous `bauval.org` scripts were disabled because their behavior, permissions, and privacy terms could not be verified from the supplied files. Do not re-enable them until the provider, publisher agreement, consent requirements, and current script contents have been reviewed. If ads or analytics are added, update the privacy notice, CSP, consent experience, and relevant jurisdictional disclosures.

The contact link opens the visitor's email application; it is not a server-side contact form.

## Security notes

- User-entered text in the new engagement UI is rendered with `textContent`.
- User-provided mood-board image URLs are restricted to HTTPS URLs on the site or `images.unsplash.com`.
- Image uploads are limited by size and MIME-type checks. MIME types can be spoofed; this is a client-side preview feature, not a secure upload pipeline.
- The service worker caches only the same-origin app shell and static app assets. It does not cache external photographs, user data, or form submissions.
- `_headers` contains a starting security-header policy for Cloudflare Pages/Netlify-style static hosting. Verify that your chosen host supports this file and test the deployed response headers. CSP may need adjustment if you intentionally add external resources.
- HSTS is included for HTTPS deployment only. Do not serve the site over plain HTTP after enabling HSTS.
- Static frontend code cannot provide server-side rate limiting, authentication, private secrets, or protection from all client-side tampering. Do not put credentials or private API keys in these files.

## PWA and offline behavior

- `manifest.json` and the two PNG icons provide install metadata.
- `sw.js` caches the same-origin app shell and local static files.
- Navigation uses network-first behavior and falls back to `offline.html` if offline.
- Static app assets use cache-first behavior; increment `CACHE_NAME` in `sw.js` for every release that changes cached files.
- A newly installed worker prompts the visitor to reload for the update. Offline photographs are not cached.
- Installation prompts and PWA support vary by browser and platform. Safari/iOS installation uses the browser's Add to Home Screen flow and may differ from Chromium.

## Deployment — free static hosting

### Cloudflare Pages (recommended)
1. Create a free Cloudflare account and a Git repository containing this folder.
2. In Cloudflare Pages, create a project connected to the repository.
3. Select the static/None framework preset; no build command is needed and the output directory is the repository root (or the project folder if nested).
4. Deploy. Cloudflare provides a free `*.pages.dev` subdomain subject to its current plan limits and terms.
5. Test HTTPS, `_headers`, the service worker, the 404 page, and PWA installation on the deployed hostname.
6. Add a custom domain only if you own one; domain registration may cost money.

GitHub Pages and Netlify can also host this static project. Check current free-tier limits and whether `_headers` is supported; GitHub Pages does not apply Cloudflare/Netlify `_headers` automatically. Configure equivalent security headers at the host/CDN where possible.

### Updating and backups
1. Keep the project in Git and commit a known-good version before changes.
2. Update the `CACHE_NAME` in `sw.js` whenever the app shell changes.
3. Push changes to the connected repository to redeploy.
4. Keep a local ZIP or Git history backup. Export local user data only from the browser where it was saved; it is not part of the website repository.

## Tests and known limitations

- JavaScript syntax checks can be run with `node --check script.js` and `node --check engagement.js`.
- `design-library-status.json` is the source of truth for the current starter count; update it whenever reviewed designs are added or removed.
- This delivery has not been verified in every Safari/iOS/Android version, and automated browser interaction testing was not available in the build environment.
- Lighthouse, Core Web Vitals, HTML validator, screen-reader, and deployed HTTP-header tests must be run against the final public deployment.
- No global popularity/trending counts are claimed because no cross-user analytics backend exists. Favorites and recommendations are browser-local. “Featured” means editorially selected in the existing data.
- There are no individually crawlable design pages, no sitemap until a real domain is known, no working server-side contact form, no cross-device accounts/sync, and no live AI integration.

## Language selector (incremental)

### Current security-header policy

Cloudflare Pages reads `_headers` from the deployed output directory. This file retains `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, HSTS, and a restrictive CSP. It currently allows only same-origin scripts, denies frames, and allows Unsplash images. If the chosen host ignores `_headers`, configure equivalent rules in its dashboard/CDN. Verify actual response headers using browser developer tools or `curl -I https://YOUR-REAL-DOMAIN/`; a checked-in file does not prove that the host applied it.
